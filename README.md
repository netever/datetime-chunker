# Разбиение DataFrame на чанки по datetime-колонке

Функция `split_by_datetime(df, column, chunk_size)` лениво отдаёт чанки фрейма, где:

- все повторения одного datetime лежат в **одном** чанке;
- даты разных чанков **не пересекаются**, чанки идут по возрастанию дат;
- каждый чанк содержит **`>= chunk_size`** строк и при этом минимален (не берёт лишнюю группу);
  исключение — последний чанк-хвост, он может быть меньше (как `00:00:03` в примере из задания).

```python
from chunker import split_by_datetime

for chunk in split_by_datetime(df, "dt", chunk_size=100_000):
    process(chunk)
```

Пример из задания (`01 01 02 02 02 03`): `chunk_size` 1–2 → 3 чанка, 3–5 → 2 чанка, ≥ 6 → весь фрейм.

## Алгоритм

Работаем не с объектами `Timestamp`, а с int64-представлением колонки (`series.array.view("i8")`) —
это view на данные pandas, без копирования. Подходит для naive и tz-aware колонок и любой единицы времени.

Жадное разбиение по отсортированному массиву ключей:

1. Чанк начинается с позиции `start`. Чтобы набрать `chunk_size` строк, он обязан включить
   позицию `pivot = start + chunk_size - 1`.
2. Граница не должна рвать группу одинаковых дат, поэтому чанк продлевается до конца группы
   значения `keys[pivot]` — это один бинарный поиск `np.searchsorted(..., side="right")`.
3. Следующий чанк начинается с найденной границы. Если `pivot` вышел за конец — остаток уходит хвостом.

Чанк из отсортированного фрейма — это `df.iloc[start:stop]`, т.е. view без копирования данных.

Если колонка не отсортирована, строится стабильный `argsort` (порядок строк внутри одной даты сохраняется),
и каждый чанк собирается через `df.take` в момент запроса — копия всего фрейма не создаётся.

## Сложность и память

`n` — строк, `k ≈ n / chunk_size` — чанков.

| Вход | Время | Доп. память |
|---|---|---|
| отсортирован, `assume_sorted=True` | **O(k·log n)** — сублинейно, данные не читаются целиком | O(1) |
| отсортирован (по умолчанию) | O(n) векторная проверка сортировки + O(k·log n) | O(1): блок проверки 64 KiB, чанки — view |
| не отсортирован | O(n log n) на argsort + O(k·log n) | 16 байт/строку на пике, 8 байт/строку во время итерации + копия одного текущего чанка |

Замеры на 1 000 000 строк (фрейм ~19 MiB, `python -m chunker`):

| Вход | Время разбиения | Пик доп. памяти |
|---|---|---|
| отсортирован | ~1–5 мс | ~0.06 MiB |
| перемешан | ~120 мс | ~15–25 MiB (зависит от размера чанка) |

Почему не `groupby` / `sort_values` / `np.unique`: `sort_values` копирует весь фрейм (×2 памяти),
`groupby` строит хеш-таблицу и коды групп на каждую строку, `np.unique(return_counts=True)` сортирует
и создаёт массивы на все уникальные даты, а последующий цикл по группам — O(число уникальных дат) в Python.
Здесь же Python-цикл идёт только по чанкам.

## Особенности

- Функция возвращает генератор: в памяти живёт только текущий чанк. Нужен список — `list(...)`.
- Чанки отсортированного фрейма — view на исходный `df`. В pandas 2.x без Copy-on-Write запись в чанк
  может изменить исходный фрейм; если чанк нужно менять — включите
  `pd.options.mode.copy_on_write = True` (поведение по умолчанию в pandas 3) или сделайте `chunk.copy()`.
- `assume_sorted=True` отключает проверку сортировки; на несортированных данных результат будет неверным.
- `NaT` считается значением меньше любой даты: все `NaT` образуют одну группу в первом чанке.
- Колонка должна иметь dtype `datetime64` (object-колонку сначала приведите через `pd.to_datetime`).
- Для очень маленьких `chunk_size` время определяется накладными расходами pandas на создание
  объекта DataFrame (~десятки мкс на чанк). Если нужны только границы — есть `chunk_bounds(keys, chunk_size)`.

## Структура

```
chunker/
  splitter.py    split_by_datetime, chunk_bounds — алгоритм
  data.py        generate_frame — генерация данных от 1 000 000 строк с повторами дат
  __main__.py    демо: генерация, разбиение, статистика по времени и памяти, выгрузка чанков в CSV
tests/
  test_splitter.py   примеры из задания, граничные случаи, несортированный вход, tz, NaT,
                     валидация, view без копий, сверка с наивным эталоном на случайных данных
  test_large.py      1 000 000+ строк: сортированный и перемешанный вход, разные chunk_size,
                     сверка с эталоном, замеры памяти через tracemalloc
  test_data.py       генератор данных
  test_cli.py        демо-скрипт и выгрузка чанков в CSV
  helpers.py         проверки инвариантов и наивный эталон, независимые от реализации
```

Тесты проверены мутационно: намеренно сломанные варианты алгоритма (сдвиг границы на 1,
`side="left"`, нестабильная сортировка, ошибка в проверке сортировки) тестами ловятся.
